# Phase 1: Define and Spec

The first session produces one document: `project-owner-expectations.md`.

## Run the Interview

Ask Claude to interview you about the project. It should ask **one question at a time** and provide answer options when possible.

Answer briefly but clearly. If your answer is unclear or incomplete, Claude should ask a follow-up question rather than make assumptions.

## Example Prompt

You are a senior software architect. Interview me about a project I want to build using `AskUserQuestion`.

Ask one question at a time and provide answer options when possible. If my answer is unclear or incomplete, ask follow-up questions. Do not make assumptions.

When you have enough information to create a complete project definition, stop the interview and produce `project-owner-expectations.md`.

## What the Document Should Cover

| Section           | What it captures                                          |
| ----------------- | --------------------------------------------------------- |
| **Project goal**  | What this is and why it exists                            |
| **Users**         | Who it is for, specific enough to be useful               |
| **Core features** | What the product must do, not nice-to-haves               |
| **Constraints**   | Hard limits such as budget, timeline, or existing systems |
| **Out of scope**  | What this explicitly does not do                          |
