# Phase 4: Implement

With a spec, architecture, and task list in place, implementation becomes a series of focused, repeatable sessions. Each one follows the same loop.

## Steps

### 1. Load Context for Each Session

Start every session with the same context block. Never assume Claude remembers the previous session.

```
You are a senior [role] working on [project name].

Before doing anything:
1. Read SPEC.md
2. Read ARCHITECTURE.md
3. Read the current task below

Current task: [paste task from task list]

Do not change anything outside the scope of this task.
```

### 2. Work Through the Task

Let Claude produce the implementation. If the task is large, break it into smaller steps within the session rather than expanding the scope.

If Claude proposes something that contradicts the spec or architecture, stop it and ask why before accepting the change.

### 3. Review and Sync

Before ending a session, do two things:

1. Read the output. Check it against the spec and architecture before committing.
2. Update `SPEC.md` or `ARCHITECTURE.md` if anything material changed. Future sessions load those files; if they are stale, context drift builds up.

## Summary

- Load the same context block at the start of every session.
- One task per session; do not expand scope mid-session.
- Review output against the spec before committing.
- Keep the docs in sync so the next session starts clean.
